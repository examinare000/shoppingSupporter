# タスク指示書: 商品検索エンドポイントの実装

## 概要
商品名と説明文を対象としたあいまい検索エンドポイント `GET /api/products/search` を新規実装する。

## エンドポイント仕様

### リクエスト
- **メソッド/パス**: `GET /api/products/search`
- **クエリパラメータ**:
  - `q` (string, 必須): 検索キーワード
  - `limit` (number, 任意, デフォルト `10`): 返却件数の上限

### 検索ロジック
- 商品の **商品名** および **説明文** を対象に **あいまい検索** を行う
- 結果は **関連度順** で返却する（デフォルトソート）

### レスポンス
- 返却フィールドは **既存の商品スキーマに準拠** する
- ページネーションは `limit` のみ（オフセット/ページ指定は持たない）

### エラー時挙動
- 検索エラーや該当なしを含むエラー時は **空配列** を返却する

### 認証
- **認証不要**

## 作業項目

### 高優先度

#### 1. 既存実装パターンの調査（plan エージェント）
- ルーティング定義の場所と既存エンドポイントの実装パターンを特定する
- 既存の商品スキーマ（型定義・モデル）の場所を特定し、レスポンス形式を確定する
- データソース層（DB / リポジトリ / 既存検索処理）の既存パターンを特定する
- あいまい検索の実装手段を、既存依存・既存パターンに合わせて選定する
- ルーティング規約・エラーハンドリング規約・バリデーション規約に従って設計する

#### 2. ハンドラ実装
- `GET /api/products/search` のハンドラを新規作成する
- クエリパラメータ `q`、`limit` のパース・バリデーション
- `limit` 未指定時のデフォルトは `10`
- 商品名 + 説明文に対するあいまい検索を実行
- 結果を関連度順で `limit` 件まで返却
- エラー時は空配列を返却

#### 3. ルーティング登録
- 既存ルーティング定義に `GET /api/products/search` を登録する

#### 4. テスト作成（write_tests エージェント）
- ハンドラの単体テスト
  - 正常系: `q` がヒットするケース、複数件返却、関連度順の確認
  - 正常系: `limit` 指定時に件数制限が効く
  - 正常系: `limit` 未指定時にデフォルト10件が適用される
  - 異常系: `q` がヒットしないケースで空配列
  - 異常系: 検索エラー発生時に空配列
  - 境界値: `q` が空文字、`limit` が 0 / 負値 / 非数値
  - 商品名のみマッチ・説明文のみマッチ・両方マッチ各ケース
- ルーティング/インテグレーションテスト
  - クエリパラメータが正しく解釈されること
  - 認証なしで200応答すること
  - レスポンス形状が既存商品スキーマと一致すること

### 中優先度

#### 5. 型定義
- リクエストクエリ・レスポンスの型定義を既存の型システムに合わせて追加する
- レスポンス型は既存商品スキーマを再利用する

## 確認方法

### 動作確認手順
1. サーバーを起動する
2. `curl 'http://localhost:<port>/api/products/search?q=<キーワード>'` を実行し、商品配列が返ることを確認
3. `curl 'http://localhost:<port>/api/products/search?q=<キーワード>&limit=3'` を実行し、最大3件で返ることを確認
4. ヒットしないキーワードで `[]` が返ることを確認
5. `q` を省略・空文字にしたケースで空配列が返ること（バリデーション仕様は既存パターンに合わせる）

### テスト確認
- ユニットテスト・インテグレーションテストが全てパスすること
- ビルド/型チェックが通ること

## 制約・注意事項
- データソース層・あいまい検索の具体実装手段（SQL `LIKE` / 全文検索 / トライグラム / 既存検索ライブラリなど）は **既存実装パターンに合わせて plan エージェントが選定** する
- ルーティング規約・エラーハンドリング規約・命名規約は既存コードベースに準拠する
- レスポンスの商品スキーマは新規定義せず、既存の商品スキーマを再利用する
