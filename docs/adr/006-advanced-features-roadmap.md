# ADR-006: 高度な機能（還元率反映・履歴・予測）のロードマップ

## ステータス
採用済み

## 背景
ユーザーは複数の EC サイトを横断して「最も安く買える場所」を探しているが、実質価格はユーザーの属性（会員ランク、所有カード等）によって大きく変動する。また、単に現在の最安値を知るだけでなく、「今が買い時か」という時間軸での判断基準も求められている。

本ドキュメントでは、以下の 3 つの高度な機能の実装ロードマップを定義する。
1. **UserProfile による還元率反映**
2. **価格履歴表示**
3. **セール時期・価格予測**

## ロードマップ

### フェーズ 1: 基盤整備と UserProfile 連携 (Backend First)

**進捗**: ✅ 完了 (100%) — 2026-05-05 完了

1. **UserProfile / Card API の実装** ✅ 完了
   - `UserProfile` への不足フィールド（楽天モバイル、PayPay連携フラグ）の追加と `Card` シードデータの校正（最新 SPU 対応）。
2. **ポイント算出ロジックの高度化** ✅ 完了
   - 2025/2026年最新基準の還元率（楽天 SPU 最大 18 倍等）を `api/lib/pricing/engine.py` に実装。

## 技術的決定事項

### 実質価格計算の責務
- **決定**: 計算ロジックの主導権は **バックエンド** に置く。
- **理由**: 還元率の計算ルールは複雑かつ頻繁に変動するため、フロントエンドにロジックを分散させると保守が困難になる。フロントエンドは API から返された `points` と `effectivePrice` を表示するのみに徹する。

### チャートライブラリの選定
- **決定**: `recharts` を採用（Phase 2 で確定）。
- **理由**: `visx` と比較してセットアップコストが低く、カスタムカラー・グリッド・ツールチップの制御が十分に可能。紙面デザインのトーン（静的、精緻）に合わせたモノクロ配色で実装済み。

### 予測アルゴリズム
- **初期実装**: 統計的な移動平均と、固定のセールカレンダーに基づくルールベースの予測から開始する。
- **将来**: 必要に応じて ML モデルの導入を検討するが、現時点では「透明性の高いルールベース」の方がユーザーの信頼を得やすいと判断。

## 影響
- **フロントエンド**: `Listing` 型に `personalPoints` などのフィールドが追加される。
- **データベース**: `PriceHistory` が大量に蓄積されるため、インデックス設計と古いデータのアーカイブ戦略が必要になる。
- **UX**: ログイン前後で価格表示が変わるため、初回訪問時のオンボーディング（「ランクを設定して正確な価格を見る」という導線）が重要になる。
