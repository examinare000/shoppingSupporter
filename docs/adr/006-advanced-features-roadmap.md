# ADR-006: 高度な機能（還元率反映・履歴・予測）のロードマップ

## ステータス
採用済み

## 背景
ユーザーは複数の EC サイトを横断して「最も安く買える場所」を探しているが、実質価格はユーザーの属性（会員ランク、所有カード等）によって大きく変動する。また、単に現在の最安値を知るだけでなく、「今が買い時か」という時間軸での判断基準も求められている。

本ドキュメントでは、以下の 3 つの高度な機能の実装ロードマップを定義する。
1. **UserProfile による還元率反映**
2. **価格履歴表示**
3. **セール時期・価格予測**

## ロードマップ

### フェーズ 1: 基盤整備と UserProfile 連携 (Backend First)

バックエンドで実質価格計算のパーソナライズを可能にする。

1. **UserProfile / Card API の実装**
   - ユーザーが自身の楽天ランクや所有カードを登録・更新できる API を構築。
2. **ポイント算出ロジックの高度化**
   - サイト別の基本倍率に加え、SPU (楽天) や Yahoo! プレミアム、特定のクレジットカード（楽天カード、Amazon Master等）による加算ロジックを実装。
3. **検索 API への統合**
   - `GET /api/products/search` が `UserProfile` を参照し、ユーザーごとのポイント・実質価格を同梱して返すように拡張。

### フェーズ 2: 価格履歴の可視化 (Frontend Focus)

蓄積された `PriceHistory` をユーザーに開放する。

1. **Price History API の実装**
   - 特定の `EcSiteProduct` または JAN コード単位での価格推移データを取得するエンドポイント。
2. **履歴チャートコンポーネントの構築**
   - `ProductDossier` 内に統合。
   - デザイン指針: 活字（Newsreader/JetBrains Mono）と親和性の高い、ミニマルなモノクロまたは単色チャート。

### フェーズ 3: データ分析と予測インテリジェンス (Analytics)

「買い時」の自動判定。

1. **価格分析エンジンの実装**
   - 過去 30/90 日の最安値、平均値との比較。
   - EC サイトの定期セール（毎月 5/10 日、お買い物マラソン等）の周期性を考慮した予測フラグ。
2. **エディトリアルな推奨表示**
   - `MarginalNote` や専用の `Ordinal` ライクなバッジを用いて、直感的なアドバイス（「Editors' Pick: Buy Now」等）を配置。

## 技術的決定事項

### 実質価格計算の責務
- **決定**: 計算ロジックの主導権は **バックエンド** に置く。
- **理由**: 還元率の計算ルールは複雑かつ頻繁に変動するため、フロントエンドにロジックを分散させると保守が困難になる。フロントエンドは API から返された `points` と `effectivePrice` を表示するのみに徹する。

### チャートライブラリの選定
- **候補**: `recharts` または `visx`。
- **方針**: 紙面デザインのトーン（静的、精緻）を崩さないよう、インタラクションよりもレンダリングの美しさとカスタマイズ性を優先する。

### 予測アルゴリズム
- **初期実装**: 統計的な移動平均と、固定のセールカレンダーに基づくルールベースの予測から開始する。
- **将来**: 必要に応じて ML モデルの導入を検討するが、現時点では「透明性の高いルールベース」の方がユーザーの信頼を得やすいと判断。

## 影響
- **フロントエンド**: `Listing` 型に `personalPoints` などのフィールドが追加される。
- **データベース**: `PriceHistory` が大量に蓄積されるため、インデックス設計と古いデータのアーカイブ戦略が必要になる。
- **UX**: ログイン前後で価格表示が変わるため、初回訪問時のオンボーディング（「ランクを設定して正確な価格を見る」という導線）が重要になる。
