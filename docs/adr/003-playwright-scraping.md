# ADR-003: 公式API連携への移行とPlaywrightの廃止

## ステータス
刷新 (Superceded by Official API Integration)

## 背景
Playwright によるスクレイピングは強力だが、以下の課題があった：
- **メンテナンス負荷**: サイトの構造変化に弱く、セレクタの修正が頻繁に発生する。
- **実行環境の制限**: Vercel (AWS Lambda) 環境でブラウザを動かすのはリソース制限やバイナリサイズの問題で困難。
- **規約遵守**: 多くのサイトでスクレイピングはグレーゾーンまたは禁止されている。

## 決定
Playwright によるスクレイピングを廃止し、Amazon, 楽天, Yahoo の公式APIを利用したデータ取得に移行する。

## 理由
- **安定性**: 公式APIは仕様が安定しており、サイトの構造変化に左右されない。
- **軽量化**: ブラウザの起動が不要になり、APIレスポンスのみで済むため高速かつ軽量。
- **Vercel適合性**: HTTPリクエストのみで完結するため、サーバーレス環境で容易に動作する。

## 影響
- 各APIの利用申請（Application ID取得等）が必要。
- APIの利用制限（リクエスト数、売上実績による制限）への対応が必要。
- スクレイピングでしか取得できなかった特定の情報の欠落（必要に応じて代替手段を検討）。
