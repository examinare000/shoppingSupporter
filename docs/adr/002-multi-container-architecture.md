# ADR-002: マルチコンテナ構成とサービス分離

## ステータス
承認済み

## 背景
スクレイピング処理はリソース消費が激しく、また各ECサイトの仕様変更による頻繁なアップデートが予想される。APIサーバー（Backend）とデータ収集（Analysis）を同じプロセスで動かすと、一力の負荷が全体に影響するリスクがある。

## 決定
Docker Compose を使用し、Frontend, Backend, Analysis, DB を独立したコンテナとして構築する。

## 理由
- **スケーラビリティ**: Analysis サービスだけをスケールアウトさせることが容易。
- **耐障害性**: スクレイピング処理がクラッシュしても、APIやフロントエンドの動作を継続できる。
- **開発の独立性**: 各サービスで最適な依存関係（例: AnalysisコンテナのみにPlaywrightが必要なライブラリを入れる）を維持できる。

## 影響
- コンテナ間通信の設定が必要。
- DBスキーマの変更時に、BackendとAnalysisの両方で同期が必要。
