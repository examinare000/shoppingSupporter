# 詳細設計: 価格履歴とチャート表示 (Phase 2)

過去の価格推移を蓄積・可視化し、ユーザーが「買い時」を判断するための機能設計。

## 1. 概要
Vercel Cron によって収集された `PriceHistory` データを抽出し、フロントエンドでミニマルなチャートとして表示する。

## 2. API 仕様 (GET /api/products/{id}/history)

### 2.1. リクエスト
- `id`: JAN コードまたは内部 Product ID
- クエリパラメタ: `days` (過去 30/90/365 日)

### 2.2. レスポンス
サイトごとの時系列データを配列で返却する。
```json
{
  "productId": "...",
  "histories": [
    {
      "date": "2024-05-01",
      "amazon": { "price": 1500, "points": 15 },
      "rakuten": { "price": 1600, "points": 160 },
      "yahoo": { "price": 1550, "points": 60 }
    },
    ...
  ]
}
```

## 3. データベース最適化

### 3.1. インデックス
`price_histories` テーブルは時間とともに巨大化するため、以下のインデックスを検討する。
- `(ec_site_product_id, created_at DESC)`: 特定商品の最新価格取得用
- `(created_at)`: パーティショニング（将来的な検討事項）

### 3.2. データ削減 (Downsampling)
Phase 2 では 1 日 1 レコードの代表値（日次最安値）に集約して返却することで、レスポンスサイズを削減する。

## 4. フロントエンド・チャート設計

### 4.1. デザイン指針 (Editorial Tone)
- **色**: モノクロまたは単色（芥子色など）を使用し、背景の紙の質感に馴染ませる。
- **グリッド**: 必要最小限の補助線。活字（JetBrains Mono）による軸ラベル。
- **インタラクション**: ツールチップによる詳細表示のみ。過度なアニメーションは避ける。

### 4.2. 技術選定
- `recharts` または `visx` を使用。
- サーバーサイドでの SVG 生成も検討したが、動的なツールチップの利便性からクライアントサイド描画を優先する。
