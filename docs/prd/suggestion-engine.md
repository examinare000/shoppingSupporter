# 最適購買パターンサジェスト機能 要件定義書 (Suggestion Engine)

## 概要
ユーザーの会員ステータス、現在の利用実績（ポイント獲得上限）、および機械学習による価格予測を組み合わせ、「いつ、どこで買うのが最もお得か」を具体的にサジェストする機能。

## 背景
EC サイトの還元率は、ユーザーの属性や月間の利用額によって動的に変化する。また、価格自体もセールの前後で変動するため、ユーザーは「今すぐ買うべきか、次のセールを待つべきか」という判断を迫られている。本機能はこの複雑な計算と予測を代行し、最適解を提示する。

## 機能要件

### 1. ユーザー状況の把握（Context Awareness）
- **代理ログイン同期**: ユーザーの許可に基づき、各 EC サイト（Amazon, 楽天, Yahoo）へ一時的に代理ログインし、今月の購入累積額と現在の会員ランクを取得する。
- **認証情報の非保持**: スクレイピングに使用した ID/PW はメモリ上でのみ処理し、永続化（保存）せずに即座に破棄する。
- **手動設定オプション**: ログイン情報を入力したくないユーザー向けに、利用額とランクを手動入力できる UI を提供する。

### 2. 価格推移予測（Price Prediction）
- **時系列予測**: 蓄積された価格履歴データを機械学習モデル（時系列予測）で分析し、向こう 14 日間のベース価格の推移を予測する。
- **予測精度の可視化**: 予測の確信度を UI 上で表現する。

### 3. 最適購買シミュレーション（Suggestion Logic）
- **ポイント上限計算**: 各サイトのキャンペーン上限（例：楽天お買い物マラソン 7,000pt 上限など）を考慮し、ユーザーの現在の利用実績から、追加購入時に得られる「真の還元率」を算出する。
- **ハイブリッドシミュレーション**: 「予測ベース価格」×「日別キャンペーン（5 と 0 のつく日等）」×「ユーザー個別還元率（上限考慮）」を 14 日分シミュレートする。
- **サジェスト提示**: 「今すぐ Amazon で購入（最安）」や「3 日後の楽天セールまで待機（実質最安）」などの具体案を提示する。

## 非機能要件

### 1. セキュリティ
- 代理ログイン機能は高度なセキュリティ基準で実装し、ユーザーの認証情報漏洩を徹底的に防止する。
- スクレイピング処理はメイン API から分離された隔離環境（Scraping Worker）で実行する。

### 2. スケーラビリティ
- 機械学習モデルの学習および推論は、Vercel Functions の制限を回避するため、専用の ML サーバーで実行する。
- 大量の価格データに対する予測処理を効率化するため、バッチ処理と推論 API を分離する。

## システム構成イメージ

```
[Frontend] <--> [Main API (Vercel)] <--> [PostgreSQL (Neon)]
                    |          ^
                    v          |
        [Scraping Worker]  [ML Server (Learning/Inference)]
```

## 受け入れ基準

| シナリオ | 条件 | 実行 | 結果 |
|---|---|---|---|
| 利用額同期 | 楽天 ID を入力し同期実行 | 購入履歴を取得 | `monthly_spent_rakuten` が更新され、上限までの残り額が反映される |
| 買い時サジェスト | 3 日後に大規模セールが控えている | 商品詳細を表示 | 「3 日後のセールまで待てば、実質価格がさらに 2,000 円下がります」と表示される |
| 上限考慮の計算 | 今月の楽天利用額が既に上限付近 | 商品の実質価格計算 | 獲得ポイントが 0 または上限キャップされた状態で実質価格が算出される |
